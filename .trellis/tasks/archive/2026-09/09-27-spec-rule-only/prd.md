# spec 只写结果：全量删除原因、后果与历史

## 目标

`.trellis/spec/` 每节只留**命令式规则 + 参数 + 示例 + 表**。删除动机推测、后果与现象描述、历史与版本考古、解释段与修辞。

范围：18 个文件 / 2355 行。先以 `cross-cutting.md` 为样板，用户验收口径后再铺其余 17 个。

## 口径（本任务的唯一权威，逐文件照此执行）

### 保留

- 命令行、参数、路径、文件 / 符号名、版本号、示例代码块
- 枚举 / 矩阵 / 字段 / 清单类表格
- 「有意留白」「不要新加的门禁规则」这类**清单**（它们本身是结论）
- 交叉引用链接
- 快照标注（如「快照 2026-09，实际以 `integration_test/app_test.dart` 为准」）
- 「不要做 X」禁令本身

### 删除

- **动机与推测**：「因为」「所以」「否则（将来）会…」「为了…才…」「之所以」
- **后果与现象描述**：可验证但非规则的内容（「不报错，只是静默少跑」「传了不起作用」「会卡数分钟且不稳定」）
- **历史与版本考古**：「曾经 / 当年 / 原 / 已移除」「2.16.1 实测」、commit 号、日期叙事
- **解释段**：整段解释「为什么这样设计」的
- **修辞**：比喻、「有门禁的错觉」这类

### 改写范式

| 原文形态 | 改成 |
|---|---|
| `X 会 Y，所以不要 X` | `不要 X` |
| `不要 X：它已移除，传了不起作用` | `不要 X` |
| `Y 是常态，硬门禁会…；升级时机由人排` | `dart pub outdated 只报告，不阻断合并；升级时机由人按 release-checklist 排` |
| `只在显式传文件名时输出……传目录不行 —— 不报错，只是静默少跑规则` | `只在显式传文件名时输出：单文件、多文件都行，传目录不行` |

最后一行是边界样例：**「只报告 / 不阻断」「必须显式传文件名」这类当前行为是规则的一部分，留；它派生的现象与解释，删。**

### 同步修订

`guides/comment-guidelines.md` 第 93 行的写法约定现在明文要求「一条能执行的规则配一两句为什么」，与本口径冲突，随本任务一起改掉。

## 风险

- **后果性线索消失**：删掉「不报错、只是静默少跑」这类可验证现象后，将来遇到反常现象时 spec 里没有对照物，需要重新踩一遍。这是本口径的既定代价，用户已确认。
- **禁令边界变窄**：只留「不要做 X」而不留判据细节时，哪些写法算违规可能被误判。涉及判据的地方保留判据本身（如「实参不是 `.notifier`」「只挡 `material` 等于没挡」这类**判定条件**）。
- **批量改写的口径漂移**：跨 18 个文件，中途若口径调整需回改；因此先做样板验收。
